# Signing releases

Neither build is signed by default. This is how to change that.

## Windows (Authenticode)

1. Obtain a code-signing certificate (OV or EV). Export it as a password-protected
   PFX.
2. Base64-encode the PFX and store it as the `WINDOWS_PFX_BASE64` repository
   secret; store the password as `WINDOWS_PFX_PASSWORD`.
3. In the `windows` job, after publishing, decode and sign:

```yaml
- name: Sign exe
  if: ${{ env.WINDOWS_PFX_BASE64 != '' }}
  shell: pwsh
  run: |
    [IO.File]::WriteAllBytes("cert.pfx",
      [Convert]::FromBase64String($env:WINDOWS_PFX_BASE64))
    & "${env:ProgramFiles(x86)}\Windows Kits\10\bin\10.0.22621.0\x64\signtool.exe" `
      sign /f cert.pfx /p $env:WINDOWS_PFX_PASSWORD /fd SHA256 `
      /tr http://timestamp.digicert.com /td SHA256 out/BomberLauncher.exe
    Remove-Item cert.pfx
```

Sign before zipping. EV certificates may require a hardware token or cloud
signing service; use the provider's `signtool` integration instead.

## AppImage (GPG)

AppImage supports detached signatures:

```sh
gpg --detach-sign --armor dist/BomberLauncher-portable-x86_64.AppImage
```

Publish the `.asc` alongside the AppImage. In CI, import the private key from a
`GPG_PRIVATE_KEY` secret, then:

```sh
export SIGN_KEY=<key-id>
ARCH=x86_64 appimagetool --sign AppDir output.AppImage
# produces output.AppImage.sig
```

## Checksums

`SHA256SUMS` is generated by the release job and attached to every release.
Users can verify with:

```sh
sha256sum -c SHA256SUMS
```
